# Deploy the NEXUS academic demo on Render

Deployment setup: prepared. No Render resources have been provisioned yet.
A connected Render account is required to create and verify the hosted services.

[Deploy NEXUS on Render](https://render.com/deploy?repo=https://github.com/arishashiraz/Nexus_Disaster)

1. Sign in to Render (GitHub sign-in is supported).
2. Open the deployment link and review the Blueprint from this repository.
3. It creates one free Docker web service and one free PostgreSQL database in
   Singapore. Check that both plans say free before creating them. If the account
   is ineligible for free resources, stop and choose a plan deliberately.
4. Deploy the Blueprint. Wait for the database and web service to be healthy.
5. Open the HTTPS URL Render assigns to the web service. Do not guess the URL
   from its name; Render can add a suffix when a hostname is already taken.
6. Confirm /api/health shows application NEXUS and database UP. Sign in using a
   fictional demo account, then check Live India weather, pollution and quakes.
7. Open that same HTTPS URL on the phone and use Install app (Chrome/Android)
   or Share > Add to Home Screen (Safari/iPhone).

The Docker image packages the React PWA inside the Spring Boot JAR, so the app
and API share one origin. PostgreSQL credentials are injected by Render. The JWT
secret is generated by Render; no real secret is committed. The database rejects
public network connections. The service listens on Render's PORT. Proxy headers
are enabled so same-origin HTTPS requests are recognized correctly.

This Blueprint explicitly enables fictional demo accounts. Their credentials
are public; use only fictional training data. It does not upload the laptop's
local database or its QA records. For real use, disable seeding on a new database,
provision private accounts and complete the production requirements in
PREDEPLOYMENT-AUDIT.md.

Free web services sleep when idle and can take time to wake. Free PostgreSQL
expires after 30 days and does not provide managed backups. Upgrade intentionally
for long-term use. No paid upgrade is included in this configuration. Account
bandwidth/build quotas and any configured billing limits still apply.

Automatic deploys are off: future code pushes do not silently change the hosted
instance. Use Render's Manual Deploy after reviewing an update.

Docker is unavailable on the development laptop. The combined JAR is tested
locally; the actual Linux image build and HTTPS checks must run on Render.
